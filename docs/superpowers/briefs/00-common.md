# Common rules for Phase 2.5 agents (visual transformation)

Read `docs/TRACKER.md` (Phase 2.5), `docs/design/brand.md` (v3) and the gallery pages `#/dashboard`, `#/motion`, `#/forms`, `#/site` (`ui-common/apps/gallery/src`) which show the exact target pattern. Use the `frontend-design:frontend-design` skill (Skill tool) first.

OWNER FEEDBACK: the UI "looks 10 to 15 years old, static, no animation, basic colours". Target: the lime/lilac/black BENTO dashboard pattern: floating rounded `AppFrame` on a lime-tinted backdrop, near-black rounded sidebar with a white active pill and lime count badges, grey canvas, WHITE 28px-radius cards (each list item its own card, clear separation and hierarchy), one black card per screen, huge numerals (`BigStat`, `CountUp`), bubble / dot-matrix / bars / progress / area charts, pill selects, round icon buttons, lime delta pills, three-dot menus, per-card icon chip, and tasteful animation (staggered entrances, counting numbers, growing bars, spring dialogs, hover spotlight, route transitions). The public site follows the cinematic pattern (Mayhem-Wheels-like: dark hero, huge type, scroll story, numbered cards, product switcher).

HARD RULES
- NO POINTLESS UI: every card, widget, promo or section must show real information or offer a real action. Remove decorative filler that means nothing. Be honest in the UI about what the product actually does (for example Waiting On only DRAFTS letters and never emails anyone; there are no real third-party apps for Consent yet).
- NO new dependencies (the lockfile is frozen; everything is exported by `@platform/ui`).
- Keep behaviour, permissions, the `productModule` contract (Routes, nav, `useTodayItems`, demo fetch, module-relative links via `ModuleLink`/`useModulePath`), accessibility, security invariants, and the intent of existing tests (update tests only where markup legitimately changed).
- VERIFY VISUALLY, MANDATORY: run the apps and screenshot every screen you touched with Playwright MCP or the built-in browser at 1440 and 390 px, light and dark; READ every screenshot with the Read tool; critique harshly (readability, separation, hierarchy, spacing, empty states, overflow); fix; repeat. For products, check BOTH the workspace in demo mode (`pnpm --filter @platform/workspace dev`, open `http://localhost:5190/?demo=1`, module routes under `/app/<id>`) and the standalone app. Never report visual quality you did not look at. Do NOT commit screenshots to git; keep them in the Playwright output directory.
- Run `pnpm exec prettier --write` on what you touch, then from `ui-common`: `pnpm lint && pnpm typecheck && pnpm test && pnpm -r build` (all green; rerun other apps' flaky tests alone). macOS: use the Edit tool or `sed -i ''`.
- You start on an EXISTING branch with partial work from an earlier agent: `git checkout <branch>` first (the branch name is in your task), read `git log` and the diff against main to see what exists, and continue; do not redo finished work. Commit after every working step. Do not push. Other agents work concurrently on other scopes; only edit your scope.
- FINAL REPORT (plain text, concise): branch and commits; what changed per area; test counts; the screenshots you viewed and what you fixed because of them; what is weak.

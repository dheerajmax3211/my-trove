# Task H: Home Pulse simulator (backend)

PROBLEM: Home Pulse needs a physical smart plug posting readings to `/v1/ingest/readings` with a device token. A user without hardware gets an empty product. BUILD a built-in simulator that uses the REAL pipeline:
- `POST /v1/appliances/{id}/simulation` (owner-authenticated like the other appliance endpoints; the appliance must belong to the caller) body `{ "days": 1..14 (default 7), "scenario": "NORMAL" | "ANOMALY" (default NORMAL) }`. It ensures the appliance has an active device flagged `simulated` (create one named "Built-in simulator" through the normal device service; a random token is generated and its hash stored, the plaintext is never returned or logged; if the appliance already has a REAL non-simulated active device return 409), then generates realistic readings by appliance type at a 5-minute cadence (FRIDGE: compressor duty cycles about 130 W on / 6 W off with jitter; AIR_CONDITIONER: 1,100-1,500 W cycles with day/night shape; WATER_PUMP: short 700 W bursts; WASHING_MACHINE: a few programme runs per day with heating and spin stages; OTHER: noisy base load), ending now, and inserts them through the same repository/service the HTTP ingest uses (idempotent, so repeating is safe). Then it runs the anomaly evaluation for that appliance immediately (the scheduled job normally runs every 5 minutes) so the baseline is learned from the simulated history; with scenario ANOMALY it also adds a believable deviation in the last hours (for example the fridge drawing continuous high power) so an alert opens. Response `{ "readingsInserted": n, "baselineStatus": "...", "alertOpened": true|false }`.
- `DELETE /v1/appliances/{id}/simulation` removes the simulated device's readings and the device, and closes alerts that came from simulated data.
- Expose `simulated: boolean` on the device view and on appliance health/readings responses so the UI can label it. Simulated readings must never leak into another user's data (owner scoping as elsewhere).
- Tests first (Testcontainers Timescale like the existing tests): a NORMAL run produces the expected row count and a learned baseline; ANOMALY opens an alert; repeating is idempotent; DELETE cleans up; 409 with a real device; other users get 404; limits on `days`; the plaintext token is never in a response or log.
Build/test: `export DOCKER_HOST=unix://$HOME/.colima/default/docker.sock TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`, `./mvnw -q -pl home-pulse,sql-jooq -am test`; record counts (before: home-pulse 111, sql-jooq 70).

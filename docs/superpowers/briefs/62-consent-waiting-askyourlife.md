# Audit: Waiting On, Consent, Ask Your Life (branch `audit/waiting-consent-ask`)
Scope: `ui-common/apps/waiting-on/**`, `ui-common/apps/consent/**`, `ui-common/apps/ask-your-life/**`, and their backends `waiting-on/**`, `consent-gateway/**`, `ask-your-life/**` (only fixes needed for these flows). Do not edit `packages/**` or `apps/workspace/**`.
Product points (make these true in the UI, in plain words, on the first screen):
- Waiting On: "Track what other people owe you (refunds, claims, approvals) and draft the follow-ups." It DRAFTS letters; the user sends them. It must not imply it emails anyone. The reply-by-email address does not work yet: say so, or remove it.
- Consent: "Decide who can read which part of your data, and take it back any time." Real flow: a third-party app asks for access; the user approves; the app can read only the approved attributes; the user can revoke; the audit log records it. Right now nothing ever asks for access. Build a small real sample app that requests access through the consent gateway (a script or a tiny service you run locally), so a request really arrives. Show that the request is real.
- Ask Your Life: "Search everything you have saved, privately." Add a note, index it, find it by what you remember. Semantic and hybrid search are a deterministic stand-in: label that honestly in the UI until Phase 4.
Do for each: sign in as the right persona (member for each product, owner or member for these), walk the full flow against the live backend, screenshot each step, read the screenshots, fix every broken step and every confusing word, and commit a script under `dev/` (for example `dev/e2e-waiting-consent-ask.sh` or a Playwright spec) that proves the flow.

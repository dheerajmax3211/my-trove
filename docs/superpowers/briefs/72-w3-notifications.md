# Wave 3 / W3: real notifications (email + in-app), shared across services
Problem: every notification (reminders, Waiting On nudges, Digital Legacy check-in reminders, trustee invitations, family invitations) goes to a log-only sender. Nothing reaches anyone.
Build:
1. `libs/platform-notify` (new Maven module, in the root reactor): a `Notification` model (recipient uid + email, kind, subject, body, link, dedupe key), a `NotificationSender` SPI, an SMTP email sender (Spring Boot mail starter), an outbox table pattern (write in the same transaction as the business change, dispatch with retries and backoff, dead-letter after N attempts), and an in-app inbox (table + API) for each user.
2. Local mail: add a Mailpit service to `dev/docker-compose.yml` (image `axllent/mailpit`, SMTP 1025, web UI 8025). Config: `app.mail.enabled`, SMTP host and port via env. In dev, mail goes to Mailpit so a human can open http://localhost:8025 and see every email.
3. Wire the producers without changing their domain logic: shared-service reminders due, waiting-on nudges and escalations, digital-legacy reminders and trustee invitation, family-treasury invitation, consent request to the owner. Each producer writes an outbox entry in its own transaction. Schema changes go in the owning service's schema with plain migrations.
4. In-app: a notifications API per user (list, unread count, mark read) in shared-service, exposed through the gateway as `/api/shared/v1/notifications`. Keep the platform token permissions in mind (the caller can read only their own inbox).
5. Tests: outbox dispatch with a fake SMTP server or Mailpit container (Testcontainers `axllent/mailpit`), retry and dead-letter, dedupe on the same key, recipient isolation, and an end-to-end test that a reminder produces an email in Mailpit.
6. Frontend: a notification bell in the workspace shell showing the unread count and a list (this touches `ui-common/apps/workspace/**`: coordinate by keeping the change to one component file, `shell/NotificationBell.tsx`, plus its mount point, and say so in your report).
Verify live: create a reminder for member@example.test, check Mailpit receives the email, and the bell shows it.
